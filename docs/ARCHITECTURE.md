# MyDock architecture

Current implementation evidence is maintained in [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md).

## Current structure

| Area | Responsibility |
|---|---|
| `Sources/MyDock/Core` | Central product name and bundle identifier. |
| `Sources/MyDock/Models` | Codable profile, item, spacer, setup, widget-catalogue types, and searchable system time-zone city catalog. |
| `Sources/MyDock/Persistence` | Main-actor profile store, serial revision writer, bounded local history/preset libraries; atomic, versioned JSON in Application Support. |
| `Sources/MyDock/DockManagement` | Native Dock preference adapter, serializer, serialized transaction gate, layout rollback journal, Apple Dock auto-hide recovery record, and Custom Dock panel. |
| `Sources/MyDock/Focus` | App Intents Focus Filter profile entity/query and profile activation bridge. |
| `Sources/MyDock/SystemServices` | Launch Services, running-app filtering, battery, local notifications, folder enumeration, global shortcuts, EventKit, market/business integrations and Keychain credentials, Weather/location, host CPU/memory/network/system readers, Codex rate limits, and local AI activity counters. |
| `Sources/MyDock/Backup` | Versioned portable profile archive with import validation and missing-reference reporting. |
| `Sources/MyDock/Services` | Shared edit sessions, coalesced widget data and refresh permits, hidden timer lifecycle, setup drafts, and typed redacted diagnostic reporting. |
| `Sources/MyDock/UI` | Menu-bar actions, Dock Manager, settings, and About surface. |
| `Tests/MyDockTests` | Profile persistence, spacer identity, backup, native Dock serializer/transaction fixture tests. |

## State ownership

Profiles and app-wide settings are encoded in `~/Library/Application Support/MyDock/state.json`. Writes are atomic. Before opening this store or starting a Dock controller, production launch checks for an existing MyDock process and acquires an exclusive `instance.lock` in the same directory. A duplicate exits without running Dock restoration. The store is envelope-first: the schema version is read before any model decode. Invalid state files are preserved under a recovery filename before MyDock starts with an empty store; future-schema or oversized files are left untouched and saving is disabled for the session. Custom Dock edge, scale, display ID, profile color, material, and desktop placement are saved here; if the selected display disappears, the controller uses the main display and watches for display changes. The Alpha Vantage API key is stored as a device-only Keychain generic-password item; it is not part of profile state or portable backups.

Native Dock profile application is isolated behind `DockPreferencesBackend`, `DockRelaunching`, and `DockTransactionJournal`. The production adapter touches only the `com.apple.dock` `persistent-apps` value. It saves the exact prior property list locally, applies, restarts Dock, rereads, verifies ordered app/spacer identity, and rolls back on failure. A shared serialized gate also protects Apple Dock auto-hide changes from overlapping native-profile restarts. Custom-main mode saves a versioned recovery record before setting `com.apple.dock` `autohide`, restores the exact prior explicit/absent value when leaving or quitting, and retries recovery on next launch. Default tests inject fake backends. The opt-in disposable-system test deliberately applies/restores the real Dock only when its environment gate is enabled.

The current native Dock preference representation is an undocumented macOS detail. It is based on the public Dockset behavior and read-only shape inspection of this Mac's Dock preferences. Default automated tests use fixture stores; the explicitly opted-in disposable-system suite is kept separate.

Backup import accepts regular files and reads in bounded chunks up to 25 MiB plus one byte before JSON decoding. The same manager validates size again for in-memory callers, profile/item caps, URLs, and favicon data before assigning fresh IDs or changing the store.

The XcodeGen project has a unit-test target for the same 13 test files used by SwiftPM. Its Test action sets `MYDOCK_UNIT_TEST_HOST=1`, and the Debug app delegate exits startup before loading profiles or starting Dock management. A separate Visual QA UI-test target launches the disposable preview with light/dark, position, and long-Countdown environment flags, then retains screenshot attachments. The generated projects and schemes were inspected here; Xcode's test runner remains unverified until full Xcode and an unlocked desktop are available.

## UI/runtime

The opt-in `DockBadgeMonitor` reads only Dock application-item status labels on macOS 14+, requires Accessibility access, and polls only while the Custom Dock is visible. The Dock accessibility attributes are undocumented and badge availability may vary by app; MyDock never reads notification contents.

`DiagnosticsService` emits fixed OSLog event codes and retains at most 200 recent events in memory. Settings → General can export a redacted JSON status report on demand. It contains app/OS versions, aggregate item counts, appearance/save status, and the recent typed codes; no arbitrary message, profile name/ID, path, URL, note, calendar title, credential, prompt, or image is serialized. This report is distinct from the portable profile backup, which intentionally includes saved note text and widget snapshots. The export path and event usefulness still need live acceptance.

The app uses a native `NSStatusItem`. First launch presents Manage Docks while setup is incomplete; after finishing setup it changes to accessory activation policy. The Custom Dock is a borderless, non-activating `NSPanel` backed by SwiftUI content. The Dock Manager is a normal native window hosting SwiftUI. `AccessibilityDisplayState` observes NSWorkspace display-option changes and applies Reduce Transparency, Increase Contrast, and Reduce Motion to the Dock; Weather also avoids translucent surfaces when requested. `WindowAccessibilityMonitor` lists/restores minimized windows only while the feature is enabled and the Dock is visible, and uses Accessibility APIs to minimize the focused app when requested. With the optional Screen Recording setting, `WindowPreviewCapturer` samples uniquely matched visible windows into a bounded memory cache and a private macOS Caches directory. Disk previews use a hash of the app bundle ID and a unique window title, contain no stored title/window ID, expire after 24 hours, and are removed when the setting is disabled or Screen Recording access is revoked. Hiding the Dock clears active memory previews but preserves opted-in disk previews for a later reveal or app restart.

Widget names and compact metadata are centralized in `WidgetRegistry`; rendering uses `DockWidgetProvider` implementations. `WidgetRegistry` currently lists 35 families; registry-derived tests assert each has a provider, at least one presentation option and a place in the semantic-layout QA export. Provider presence is not native acceptance: per-family workflow and native scenarios are tracked in the execution ledger and remain unaccepted. Shopify uses a same-organization client-credentials grant and read_orders-only GraphQL query; Stripe and Paddle use read-only APIs and keep credentials in Keychain. AI Limits reads Codex app-server quota data, Claude Code's configured local status-line snapshot, and personal GitHub Copilot AI-credit consumption from the documented billing endpoint when a fine-grained Plan: read token and allowance are configured. Copilot tokens stay in Keychain; its user-entered allowance and usage snapshot are profile configuration. AI Activity parses only usage fields from local Codex, Claude Code, and Grok records. It does not retain prompt/tool content. Other provider quota/activity sources remain unavailable where no supported reader is present. Widget snapshots may be backed up as profile data, while credentials remain device-local and excluded. Local weather, EventKit, Shortcuts, Now Playing, AirDrop, Trash, battery, window, and system metrics behavior follows the feature matrix. `RefreshScheduler` coalesces transient widget and system polling into one cancellable timer, pauses scheduled work while the Custom Dock is hidden, and leaves static views idle.

## Validation isolation

`AppRuntimeEnvironment` is the single boundary for validation runs. Setting `MYDOCK_VALIDATION_ROOT` (or a DEBUG visual-preview/render-QA/unit-test host flag) redirects Application Support and window-preview caches to a private directory and replaces `UserDefaults.standard` with a memory-only store, so no preference domain is written. In that mode `requireNativeEffects()` and `requireCredentials()` throw, so native Dock/app/window actions, permission requests and Keychain-backed connections fail closed. Native acceptance uses a separate explicit opt-in harness with injected backends.

## Build and checks

- `./BuildMyDock.sh` compiles macOS 13+ arm64 and x86_64 Release slices, combines them into a universal executable, and creates an ad-hoc signed `build/MyDock.app` by default. `--output` selects a separate bundle. The script checks running MyDock executables before and after compilation and refuses to overwrite an active bundle.
- `./TestMyDock.sh` passed the suite of 190 registered Swift Testing tests in 13 suites on 30 September 2026 (two tests are gated opt-ins). Coverage includes profile persistence/recovery, single-instance locking, Dock transaction and auto-hide recovery, freeze-overlay cleanup, Focus off behavior, widget configuration and backup, AI local-usage parsers/quota windows, Shopify/Stripe/Paddle/market fixtures, timer/hydration/calendar/reminder/weather/shortcut/system/network/window policies, Dock Manager selection/drafts, locale-aware Clock formatting, Trash tile geometry, and privacy/security boundaries. Fake adapters keep tests away from real Dock preferences and external accounts. The test library supplied by these Command Line Tools links for macOS 14, while the host is macOS 26.5.1 and the app target remains macOS 13.
- `MyDock.xcodeproj` is generated from `project.yml` by `GenerateXcodeProject.sh`; the script takes the product name, bundle identifier, and version from `Product.swift`. The app target includes the Focus Filter intent source and original icon. XcodeGen generation and project/plist syntax were checked locally, but `xcodebuild` and App Intents metadata generation cannot run here because only Command Line Tools are installed. See [Xcode build and Focus verification](XCODE_BUILD.md).

- Live checks cover a DEBUG-only isolated preview of all onboarding steps, the Manager, Settings, widget library, bottom/left/right Dock layouts, light/dark appearance, overflow navigation, Clock popouts, and Manager add/save/discard, rename, selection, and group movement. Earlier app builds also verified the Settings/Permissions route and Accessibility deep link. Shift-click range selection, profile persistence across app relaunch, and most desktop-only behavior still need acceptance.
- Real Dock apply/rollback has not been run on the user's actual Dock.
- Custom Dock auto-hide, desktop-level placement, Apple Dock auto-hide recovery, Focus Filter registration, reveal handle, folder browsing, App Folder, per-profile shortcuts, trackpad profile switching, fullscreen edge dwell, optional ScreenCaptureKit desktop freeze, and optional minimized-window preview cache compile and have fixture coverage where applicable, but require desktop acceptance. The opt-in app badge reader uses bounded Dock Accessibility status-label lookups on macOS 14+; actual labels and permission behavior still need desktop acceptance. Mission Control uses best-effort Dock-owned overview window metadata and still needs real-system acceptance. Apple Dock overlap detection and hide behavior need desktop verification. Live service credentials, the Focus Settings flow, multi-display behavior, and most widget actions remain unverified.
- Local builds are ad-hoc signed. The full-Xcode distribution script and CI matrix are present; publisher signing/notarization, clean installation, CI execution and older/Intel runtime acceptance are unverified.

## Roadmap state and runtime ownership

`ProfileEditSessionCoordinator` owns drafts across manager navigation and lifecycle exits. Independent per-profile autosave jobs debounce edits for 500 ms and survive navigation. Saving performs a three-way merge against the latest profile, retains concurrent widget updates, and leaves a conflicting/failed draft dirty. `RevisionedStateWriter` serializes validation, compact JSON encoding and atomic writes on a utility queue. Runtime snapshots are coalesced for 150 ms and revision checks prevent older work from overwriting a newer save. Explicit critical saves wait for the disk result; their caller can therefore wait on disk latency. Quit flushes the latest revision and offers recovery on failure. Onboarding and resolved preset creation persist a candidate before publishing it.

`DockRenderModel` supplies ordered entries, lengths and centers to the renderer and panel controller. It includes media visibility, pinned-end insertion, running-app/window boundaries, stable runtime identities and final automatic Trash. A presentation signature prevents data-only snapshots from resetting panel geometry. `DockLayoutPreview` uses the same renderer and geometry with inert sample data. The shared scroll viewport clips along its scroll axis while reserving cross-axis hover space: scrolling works, while launch, popout, drag mutation, resize and native apply are disabled. Debug previews use separate per-process state/history/preset directories, removed on exit.

`WidgetDataCoordinator` follows visible content independently of popouts. Identical account/period or symbol/currency requests share work; four permits bound provider concurrency. It cancels obsolete queries, respects the fastest visible subscriber interval, pauses hidden Dock jobs, backs off failures, retains successful partial watchlist data and exposes freshness/errors. Configuration fields are checked again before applying a snapshot. `WidgetLifecycleCoordinator` owns running Focus/Countdown deadlines across all profiles, including hidden profiles, and reschedules when timer duration changes. Notification generation checks remain separate from in-app completion.

Native recovery health blocks a new transaction until its journal is resolved. Native applied association is recorded only after verified success. AX enumeration and activation run away from the main actor with bounded messaging; automation uses a cancellable subprocess with output/time limits. AI activity scanning has byte, line, enumeration-time, read-time, recursion and cancellation bounds.

Local history retains up to 25 sanitized revisions for 14 days; personal presets retain up to 50 layouts. Each library is capped at 8 MiB with private permissions. Notes are excluded by default, and provider snapshots, connection IDs, hydration history/undo, calendar selections, shortcut names and running timer state are stripped. App/file/link locations remain part of a reusable layout. Restore creates fresh identities instead of overwriting an active profile.


## Dock workspace presentation

The main window has one sidebar and a Dock canvas. `DockCanvas` selects and reorders the actual item composition; `DockCanvasDragView` tracks internal pointer moves/releases across the entire Dock, including gaps/end, snapshots the lifted tile and validates the captured profile before dropping. The same view registers a native pasteboard destination for ordered Finder/browser URLs; the empty workspace also accepts external drops. The live Dock retains its typed group payload. `AddLibrary` supplies app discovery, widget previews, and Command-K actions with an AppKit search field for immediate arrow/Return handling. `DockAppearanceInspector` and typed item configuration targets keep global, profile, and item controls separate. The former permanent item grid and redundant top navigation are removed. The older widget variant gallery is DEBUG-only visual QA.

`DockVisualIdentity` separates semantic visual identity from persisted UUIDs, disambiguating repeated tiles in linear time. The canvas and live panel reuse shared tiles across profile changes with matched geometry and damped springs. `DockMaterialSurface` shares material and owns the single editor/live Dock outline; each Dock's theme is scoped independently from the editor. `DockDesign.Outline` strengthens control, widget and Dock boundaries for Increase Contrast. `DockAccessibilityStyle` reads system contrast/transparency in Release; a DEBUG-only override allows isolated render coverage without changing system preferences. Reduce Motion disables structural motion; Reduce Transparency uses an opaque surface. Undo applies inverse three-way merges and preserves unrelated live widget updates. No schema migration accompanies this presentation rebuild.
