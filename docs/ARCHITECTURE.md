## State ownership

Profiles and app-wide settings are encoded in `~/Library/Application Support/MyDock/state.json`. Writes are atomic. Before opening this store or starting a Dock controller, production launch checks for an existing MyDock process and acquires an exclusive `instance.lock` in the same directory. A duplicate exits without running Dock restoration. The store is envelope-first: the schema version is read before any model decode. Invalid state files are preserved under a recovery filename before MyDock starts with an empty store; future-schema or oversized files are left untouched and saving is disabled for the session. Custom Dock screen edge, scale, display ID, profile color, material, edge style, widget surface, tint mode and strength, floating inset, and desktop placement are saved here, and a profile may keep its own `ProfileAppearance` snapshot instead of inheriting them. Each widget saves its layout, icon appearance, accent, label visibility and glass tint. The appearance fields are optional or defaulted on decode and an unknown raw value falls back to the default (Hairline edge, Tile surface, no inset, custom tint), so older state files load unchanged and the schema version stays 1. If the selected display disappears, the controller uses the main display and watches for display changes. The Alpha Vantage API key is stored as a device-only Keychain generic-password item; it is not part of profile state or portable backups.

Provider readings (Stripe/Paddle/Shopify, stock and watchlist quotes, AI limit and activity snapshots, weather forecast) are runtime cache, not authored state. `WidgetRuntimeCache` stores them in `runtime-cache.json` beside `state.json`: versioned, keyed by widget item ID, each reading tagged with the identity it was fetched for (connection, symbol, location), capped at 4 MiB / 2,000 entries, private 0600/0700, written atomically on a utility queue (750 ms coalescing, flushed at quit; a flush failure is only logged and diagnosed). An unreadable, oversized or future-version cache is set aside as `runtime-cache.json.corrupt-*` and replaced by an empty one. Providers publish only through `ProfileStore.publishRuntimeReadings`, which writes the cache and never touches authored state, history, undo or edit sessions. Views read a projection (`presentationItem`, `presentationProfile`, `presentationConfiguration`) that overlays identity-matched cache readings on the authored configuration. `ProfileStore.updateWidgetConfiguration` classifies an edit the same way: if only readings differ it updates the cache and does not commit, bump the revision or write `state.json`; any authored change commits. The writer always strips readings before encoding state, and backups, history and presets exclude them. At launch, readings embedded by older files are merged into the cache (the newer `fetchedAt` wins per reading), authored state is stripped, and a legacy file is rewritten once without them. The reading fields remain optional and decodable on `WidgetConfiguration`: an older app reading a stripped file simply sees widgets as not yet refreshed. Item and profile deletion prune entries; `clearPersistedSnapshots` and connection removal clear them. Other runtime-only data follows the same rule: a Calendar event's calendar colour (`CalendarColorSnapshot`, sRGB components read from `EKCalendar.cgColor` with each event by `CalendarRemindersService`) lives only in the view's event state. It is not `Codable`, so it never reaches `state.json`, the cache, backups, history or presets, and it is absent when EventKit reports none.

Native Dock profile application is isolated behind `DockPreferencesBackend`, `DockRelaunching`, and `DockTransactionJournal`. The production adapter touches only the `com.apple.dock` `persistent-apps` value. It saves the exact prior property list locally, applies, restarts Dock, rereads, verifies ordered app/spacer identity, and rolls back on failure. A shared serialized gate also protects Apple Dock auto-hide changes from overlapping native-profile restarts. Custom-main mode saves a versioned recovery record before changing the `com.apple.dock` visibility keys it owns (`autohide`, `autohide-delay` and `no-bouncing`, captured by `NativeDockVisibilitySettings`), restores each exact prior explicit/absent value when leaving or quitting, and retries recovery on next launch. Default tests inject fake backends. The opt-in disposable-system test deliberately applies/restores the real Dock only when its environment gate is enabled.

The current native Dock preference representation is an undocumented macOS detail. It is based on the public Dockset behavior and read-only shape inspection of this Mac's Dock preferences. Default automated tests use fixture stores; the explicitly opted-in disposable-system suite is kept separate.

Backup import accepts regular files and reads in bounded chunks up to 25 MiB plus one byte before JSON decoding. The same manager validates size again for in-memory callers, profile/item caps, URLs, and favicon data before assigning fresh IDs or changing the store.

The XcodeGen project has a unit-test target for the same `Tests/MyDockTests` sources used by SwiftPM. Its Test action sets `MYDOCK_UNIT_TEST_HOST=1`, and the Debug app delegate exits startup before loading profiles or starting Dock management. A separate Visual QA UI-test target launches the disposable preview with light/dark, position, and long-Countdown environment flags, then retains screenshot attachments. It is a manual target: CI does not build or run it, and it has not been run since its flows were rewritten (see [build evidence](RELEASE_AUDIT.md)).

## UI/runtime

The opt-in `DockBadgeMonitor` reads only Dock application-item status labels on macOS 14+, requires Accessibility access, and polls only while the Custom Dock is visible. The Dock accessibility attributes are undocumented and badge availability may vary by app; MyDock never reads notification contents.

`DiagnosticsService` emits fixed OSLog event codes and retains at most 200 recent events in memory. Settings → General can export a redacted JSON status report on demand, after a review sheet. It contains app/OS versions, aggregate item counts, appearance/save status, and the recent typed codes; no arbitrary message, profile name/ID, path, URL, note, calendar title, credential, prompt, or image is serialized. This report is distinct from the portable profile backup, which intentionally includes saved note text but not provider readings. The export path and event usefulness still need live acceptance.

The app uses a native `NSStatusItem`. First launch presents Manage Docks while setup is incomplete; after finishing setup it changes to accessory activation policy. The Custom Dock is a borderless, non-activating `NSPanel` backed by SwiftUI content. The Dock Manager is a normal native window hosting SwiftUI. `AccessibilityDisplayState` observes NSWorkspace display-option changes and applies Reduce Transparency, Increase Contrast, and Reduce Motion to the Dock; Weather also avoids translucent surfaces when requested. `WindowAccessibilityMonitor` lists/restores minimized windows only while the feature is enabled and the Dock is visible, and uses Accessibility APIs to minimize the focused app when requested. With the optional Screen Recording setting, `WindowPreviewCapturer` samples uniquely matched visible windows into a bounded memory cache and a private macOS Caches directory. Disk previews use a hash of the app bundle ID and a unique window title, contain no stored title/window ID, expire after 24 hours, and are removed when the setting is disabled or Screen Recording access is revoked. Hiding the Dock clears active memory previews but preserves opted-in disk previews for a later reveal or app restart.

Widget names and compact metadata are centralized in `WidgetRegistry`; rendering uses `DockWidgetProvider` implementations. `WidgetRegistry.all` lists every family (36 at 7 October 2026; the README's widget table is checked against it); registry-derived tests assert each has a provider, at least one presentation option and a place in the semantic-layout QA export. Provider presence is not native acceptance: per-family workflow and native scenarios are tracked in the execution ledger and remain unaccepted. Shopify uses a same-organization client-credentials grant and read_orders-only GraphQL query; Stripe and Paddle use read-only APIs and keep credentials in Keychain. AI Limits reads Codex app-server quota data, Claude Code's configured local status-line snapshot, and personal GitHub Copilot AI-credit consumption from the documented billing endpoint when a fine-grained Plan: read token and allowance are configured. Copilot tokens stay in Keychain; its user-entered allowance and usage snapshot are profile configuration. AI Activity parses only usage fields from local Codex, Claude Code, and Grok records. It does not retain prompt/tool content. Other provider quota/activity sources remain unavailable where no supported reader is present. Widget readings are runtime cache and are not backed up, and credentials remain device-local and excluded. Local weather, EventKit, Shortcuts, Now Playing, AirDrop, Trash, battery, window, and system metrics behavior follows the feature matrix. `RefreshScheduler` coalesces transient widget and system polling into one cancellable timer, pauses scheduled work while the Custom Dock is hidden, and leaves static views idle.

## Validation isolation

`AppRuntimeEnvironment` is the single boundary for validation runs. Setting `MYDOCK_VALIDATION_ROOT` (or a DEBUG visual-preview/render-QA/unit-test host flag) redirects Application Support and window-preview caches to a private directory and replaces `UserDefaults.standard` with a memory-only store, so no preference domain is written. In that mode `requireNativeEffects()`, `requireCredentials()` and `requireNetwork()` throw, so native Dock/app/window actions, permission requests, Keychain-backed connections and default production network calls fail closed. Native acceptance uses a separate explicit opt-in harness with injected backends.

Render QA is DEBUG-only. `MYDOCK_RENDER_QA=<directory>` plus one `MYDOCK_<MODE>_QA=1` makes `PremiumVisualQA.export` run an exporter from `UI/PremiumVisualQA.swift` or `UI/RedesignQA/*` (Dock styles, widget surfaces, gallery, widget sheet and popouts, family faces, Settings, motion) or the `DesignSystemGallery` specimens, then quit. The exporters, the `DockAccessibilityPreview` override (Reduce Transparency, Increase Contrast and Reduce Motion without touching system preferences), the snapshot-rendering flag and the Calendar, Alarm, Trash, Now Playing and Battery fixtures all sit inside `#if DEBUG`, so Release contains none of them. Exports run under the validation root with an inert store and fixture data. They draw the material fallback because offscreen bitmaps cannot capture native Liquid Glass.

## Build and checks

- `./BuildMyDock.sh` compiles macOS 13+ arm64 and x86_64 Release slices, combines them into a universal executable, and creates an ad-hoc signed `build/MyDock.app` by default. It assembles, signs and verifies the bundle in `.build/app-stage/` and only then replaces the output, so a failed step leaves the previous app intact. Its Info.plist is `Xcode/MyDock-Info.plist` (generated from `project.yml`) with the build settings filled in; the build number counts commits. The source needs the macOS 26 SDK; every Liquid Glass call sits behind `#available(macOS 26.0, *)` with a material fallback. `--output` selects a separate bundle. The script checks running MyDock executables before and after compilation and refuses to overwrite an active bundle.
- `./TestMyDock.sh` runs the Swift Testing suites on the host architecture under a private validation root with `MYDOCK_UNIT_TEST_HOST=1`, finds `Testing.framework` in either the Command Line Tools or the Xcode layout, and forwards extra arguments to `swift test` (for example `--filter <Suite>`). Coverage includes profile persistence/recovery, single-instance locking, Dock transaction and auto-hide recovery, widget configuration and backup, appearance-model compatibility, design tokens, Dock surface and panel geometry, gallery model and keymap, widget chrome, accent resolution, sheet and popout layout, AI local-usage parsers/quota windows, provider fixtures (Shopify/Stripe/Paddle/market, weather, calendar), timer/hydration/shortcut/system/network/window policies, Dock Manager selection/drafts, settings scope/undo, and privacy/security boundaries. Fake adapters keep tests away from real Dock preferences and external accounts; the live native-Dock and synthetic performance suites are opt-in. Tests build for macOS 14 (the Swift Testing runtime); the app target remains macOS 13.
- `MyDock.xcodeproj` is generated from `project.yml` by `GenerateXcodeProject.sh` and is not checked in; run the script before opening it. Both build scripts read the product name, bundle identifier and version from `Product.swift` through `Scripts/product-identity.sh`. The app target includes the Focus Filter intent source and original icon. CI (`validate.yml`, macOS 26 arm64 and Intel runners) runs the tests, the universal build, the Xcode Release build and its App Intents metadata check. See [Xcode build and Focus verification](XCODE_BUILD.md).

## Known limitations

- Render exports are DEBUG-only and draw the material fallback. Native Liquid Glass compositing (including whether widget glass blends with the Dock glass), hover and morph feel, popout placement, VoiceOver, keyboard-only Add Item and Settings flows, side Docks, multi-display behavior, Intel and macOS 13–15 fallbacks, Shift-click range selection, editor group/end pointer drag and profile persistence across relaunch still need desktop acceptance. Calendar and Reminders have been rendered only from DEBUG fixtures, not real EventKit data or calendar colours.
- Real Dock apply/rollback has not been run on the user's actual Dock.
- Custom Dock auto-hide, desktop-level placement, Apple Dock auto-hide recovery, Focus Filter registration, reveal handle, folder browsing, App Folder, per-profile shortcuts, trackpad profile switching, fullscreen edge dwell, optional ScreenCaptureKit desktop freeze, and optional minimized-window preview cache compile and have fixture coverage where applicable, but require desktop acceptance. Real-device overflow scrolling, popout placement, and window behavior remain unverified. The opt-in app badge reader uses bounded Dock Accessibility status-label lookups on macOS 14+; actual labels and permission behavior still need desktop acceptance. Mission Control uses best-effort Dock-owned overview window metadata and still needs real-system acceptance. Apple Dock overlap detection and hide behavior need desktop verification. Live service credentials, the Focus Settings flow, and most widget actions remain unverified.
- Local builds are ad-hoc signed. The full-Xcode distribution script is present; publisher signing/notarization, clean installation and older/Intel runtime acceptance are unverified.

## Roadmap state and runtime ownership

`ProfileEditSessionCoordinator` owns drafts across manager navigation and lifecycle exits. Independent per-profile autosave jobs debounce edits for 500 ms and survive navigation. Saving performs a three-way merge against the latest profile, retains concurrent widget updates, and leaves a conflicting/failed draft dirty. `RevisionedStateWriter` serializes validation, compact JSON encoding and atomic writes on a utility queue. Runtime snapshots are coalesced for 150 ms and revision checks prevent older work from overwriting a newer save. Explicit critical saves wait for the disk result; their caller can therefore wait on disk latency. Quit flushes the latest revision and offers recovery on failure. Onboarding and resolved preset creation persist a candidate before publishing it.

`DockRenderModel` supplies ordered entries, lengths and centers to the renderer and panel controller. It includes media visibility, pinned-end insertion, running-app/window boundaries, stable runtime identities and final automatic Trash. A presentation signature prevents data-only snapshots from resetting panel geometry. Running-app matching against pinned apps (`DockRunningAppCache`) and missing-target checks (`DockMissingTargets`) are recomputed only when apps, items or volumes change, never per hover render. `DockLayoutPreview` uses the same renderer and geometry with inert sample data. The shared scroll viewport clips along its scroll axis while reserving cross-axis hover space: scrolling works, while launch, popout, drag mutation, resize and native apply are disabled. Debug previews use separate per-process state/history/preset directories, removed on exit.

`WidgetDataCoordinator` follows visible content independently of popouts. Identical account/period or symbol/currency requests share work; four permits bound provider concurrency. It cancels obsolete queries, respects the fastest visible subscriber interval, pauses hidden Dock jobs, backs off failures, retains successful partial watchlist data and exposes freshness/errors. Configuration fields are checked again before applying a snapshot. `WidgetLifecycleCoordinator` owns running Focus/Countdown deadlines across all profiles, including hidden profiles, and reschedules when timer duration changes. Notification generation checks remain separate from in-app completion.

Native recovery health blocks a new transaction until its journal is resolved. Native applied association is recorded only after verified success. AX enumeration and activation run away from the main actor with bounded messaging; automation uses a cancellable subprocess with output/time limits. AI activity scanning has byte, line, enumeration-time, read-time, recursion and cancellation bounds.

Local history retains up to 25 sanitized revisions for 14 days; personal presets retain up to 50 layouts. Each library is capped at 8 MiB with private permissions. Notes are excluded by default, and provider snapshots, connection IDs, hydration history/undo, calendar selections, shortcut names and running timer state are stripped. App/file/link locations remain part of a reusable layout. Restore creates fresh identities instead of overwriting an active profile.

## Dock workspace presentation

The main window has one sidebar and a Dock canvas. `DockCanvas` selects and reorders the actual item composition; `DockCanvasDragView` tracks internal pointer moves/releases across the entire Dock, including gaps/end, snapshots the lifted tile and validates the captured profile before dropping. The same view registers a native pasteboard destination for ordered Finder/browser URLs; the empty workspace also accepts external drops. The live Dock retains its typed group payload. `DockAppearanceInspector`, `DockItemInspector` and typed configuration targets keep global, profile, and item controls separate. The variant catalog `WidgetGalleryView` is DEBUG-only visual QA.

`DockVisualIdentity` separates semantic visual identity from persisted UUIDs, disambiguating repeated tiles in linear time. The canvas and live panel reuse shared tiles across profile changes with matched geometry and damped springs (`DockMotionPolicy`). `DockSurfaceLayers` resolves the Dock surface from material, edge style, tint and opacity and draws a layer only when it contributes: Clear is the native glass alone, with no backing, tint or stroke. `DockMaterialSurface` renders it for the editor and the live Dock and owns the single Dock outline; each Dock's theme is scoped independently from the editor (`DockColorSchemePolicy`). `DockPanelGeometry` places the panel, including the floating inset, the reveal strip at the screen edge and the hover area across the gap. For glass materials (not under Reduce Transparency) the item stack sits in one `DockGlassGroup`, while the surface glass is drawn behind it so modules do not fuse into the Dock (`DockGlassComposition`). `DockQuickStyle` (Clear, Glass, Frosted, Solid, Midnight) names preset combinations of the appearance fields; the Appearance page, first-run onboarding and starter presets apply them. `DockDesign.Outline` strengthens control, widget and Dock boundaries for Increase Contrast. `DockAccessibilityStyle` reads system contrast, transparency and motion in Release; a DEBUG-only override allows isolated render coverage without changing system preferences. Reduce Motion disables structural motion; Reduce Transparency uses an opaque surface. Undo applies inverse three-way merges and preserves unrelated live widget updates.

## Product wave (PX-1–PX-8)

- **Dock essentials** (`DockManagement/DockEssentials.swift`, `DockItemContextMenus.swift`): pure policies for dropping files on an app tile (`AppLauncher` opens them with the app), the running-app menu order (`RunningApplicationMenuPolicy`; Force Quit confirms in `AppLauncher.forceQuit`), and the runtime-only recent-apps tracker, which is never persisted or exported.
- **Window previews on hover** (`DockWindowPreviewPolicy`, `DockWindowPreviewController`, `CustomDock/DockWindowPreviewPanel.swift`): the policy owns hover timing, geometry and the permission-to-presentation mapping; the shared controller, driven by the live Custom Dock, owns every native effect. It installs no monitor or timer while idle, never requests a permission from a hover, captures thumbnails only while the panel is open into a memory cache, and clears that cache when the setting turns off.
- **Audio Output** (`SystemServices/AudioOutputService.swift`): a shared main-actor Core Audio service that lists output devices, switches the default output (alerts follow only when they already followed it), and sets volume and mute. It observes Core Audio only while a visible widget or popout subscribes and the Dock is shown, and never opens an input.
- **Automatic switching** (`Services/AutomaticSwitching.swift`, `AutomaticSwitchingController.swift`): persisted rules (off by default, Custom Docks only) evaluated by a pure engine with dwell, priority, manual override and an open-draft deferral; the controller is a thin observer with one timer and injected system inputs, started at launch by the app delegate.
- **Start Workspace** (`SystemServices/WorkspaceStarter.swift`, `UI/WorkspaceViews.swift`): a plan and a per-run object that opens a Dock's targets in order behind one launcher seam, brings running apps forward instead of relaunching, never quits or closes anything, and switches Docks only on request.
- **Portable Dock packages** (`Backup/PortableDockPackage.swift`, `UI/PortableDockSheets.swift`): single-Dock export and import on the existing backup format. Import always creates a new Dock with a fresh identity and strips account IDs, provider readings and credentials.
- **Next meeting** (`SystemServices/NextMeeting.swift`): pure selection of the next relevant event and of a recognised https meeting link for Join; the Calendar widget calls it with EventKit events.

## Design system

`UI/DockDesign.swift` holds the tokens (`DockDesign`): `Space`, `Radius`, `Outline`, `Motion` (springs for hover, appear, morph, transform, reorder and disclosure; `animation(_:reduceMotion:)` returns nil under Reduce Motion so changes are instant), `Module` (Control Center module metrics: radius concentric with the Dock, Dock radius minus Dock padding; 22/18/13 pt semibold monospaced-digit values; an 11–12 pt label; at most two text lines; nothing under 10 pt), `Glass` and `Grouped` (inset-form metrics), plus the page, sidebar and control colours and `DockAccessibilityStyle`, the one reader of Reduce Transparency, Increase Contrast and Reduce Motion. Components live in `UI/DesignSystem/`. `dockGlass(_:in:tint:interactive:)` is the one glass surface: native Liquid Glass behind `#available(macOS 26.0, *)`, `.ultraThinMaterial` before, an opaque fill under Reduce Transparency, and a visible edge under Increase Contrast. `DockGlassGroup` wraps `GlassEffectContainer`; `GlassModule` is the widget container shape; `GroupedSection`/`GroupedRow` form the inset grouped form; `PillButton`, `SizePager`, `StyleSwatch` and `dockHover` complete the set. `DockPresentationEnvironment.swift` defines the environment values that carry Dock and per-widget presentation to faces: `dockWidgetSurface`, `dockModuleRadius`, `widgetAccent`, `widgetShowsLabel` and `widgetGlassTint`. `DesignSystemGallery` is the DEBUG-only specimen sheet.

## Widget appearance and popouts

`WidgetCompactView` resolves a widget's presentation once, from its `WidgetConfiguration` and the effective settings (`WidgetPresentationValues`), and injects it through the environment; faces read the environment, never settings. `WidgetContainer` switches on the Dock's widget surface: `tile` is the original tile, `glass` a `GlassModule` (optionally tinted by the accent), `plain` sits directly on the Dock glass. `WidgetPalette` holds one desaturated hue per family category plus the semantic `warning`, `critical` and `positive` colours. `WidgetPalette.resolved(kind:accent:active:)` is the one accent resolver: `.mono` is primary, `.profile` is a profile colour, and `.auto` (the default) is neutral at rest and takes the family colour only while the widget is active (playing, running, an armed alarm, a toggled-on glyph). The Color icon treatment and the Accent glass tint are explicit requests for colour and stay coloured; semantic colours never pass through the resolver and stay coloured for state. New widgets are created with the Mono icon appearance; saved widgets keep theirs. `WidgetAppearanceControls` (accent, icon, label, glass tint) writes through `ProfileStore.updateWidgetConfiguration`, so edit sessions, undo and merge observe every change.

Popouts follow one pattern: reading first, settings behind one disclosure, one refresh control. The popover's native material is the single surface (`WidgetPopoverSurface` only fills opaque under Reduce Transparency), and `WidgetPopout` is the shell: a header with the family label, freshness, one refresh circle, Customize and Close, above the family's `popoutView` content, held at its natural height so the hosting window cannot loop in layout. Family content draws no card, header or outer padding. It leads with `WidgetPopoutHero`, one centred value with at most one line, where a value without digits (such as "Connect Stripe") uses the calmer 17 pt status style. Primary actions follow, then setup rows inside a single collapsed `WidgetPopoutSettingsDisclosure`. Coordinator families get their freshness and refresh from the shell; families that load their own reading publish it with `.widgetPopoutRefresh(...)` and draw no Refresh row. `WidgetConfigurationSheet` shows the same content with the settings expanded and no repeated hero (`widgetPopoutContext` is `.dock` or `.sheet`): a live preview, a `SizePager` over the family's layouts, Content, Appearance, Data and Remove Widget. The popout's Customize panel reuses that pager and the Appearance section.

## Add Item window and Settings

`AddLibrary` is the Add Item window; its ⌘K mode is `CommandLibrary`, unchanged. Browse mode is a gallery whose glass header holds a search pill (an AppKit field that keeps arrow, Return and Escape routing), a Widgets · Apps · More segmented control and a capability filter menu; native profiles show Apps and More only. Widgets lists a deterministic Suggested row (families not yet on the Dock; hidden for native profiles, while searching or filtering, and when adding is not allowed) and category sections of live-sample tiles. Apps is the installed-app scan, with version and folder shown only to separate same-named apps, and More holds spacers and pickers. A tile opens an in-place detail with a `SizePager` and an Add Widget `PillButton`; double-click or ⌘Return adds the default layout, and Return or Space on a focused tile shows its sizes. Previews draw the configuration a new widget is created with, so what is shown is what is added. Pure decisions (tabs, suggestions, sections, previews, keymap) live in `WidgetGalleryModel`; views are in `UI/WidgetGallery/`. `allowsAdding` is enforced in browse mode, and `WidgetDiscovery` filters by capability, never by account or permission state.

Settings is a shell plus one file per page. `SettingsView` keeps the sidebar (Your Dock: Dock Setup, Appearance, Behavior; App: General, Shortcuts; Connections: Integrations, Permissions), search and routing; `UI/Settings/` holds a `SettingsView` extension per page (`dockPage`, `appearancePage`, `behaviorPage`, `generalPage`, `shortcutsPage`, `integrationsPage`, `permissionsPage`) and `SettingsShared.swift`. Pages are `GroupedSection`/`GroupedRow` forms with short footers, as are the Dock and item inspectors. The Appearance page runs hero preview (`DockLayoutPreview` over a sample wallpaper), Style (`DockQuickStyle` swatches), Glass, Layout, Widgets and Scope (app defaults or one Dock's snapshot, with Undo). `SettingsSearchCatalog` maps each control to a page and an `.id` section anchor that search results scroll to, so a new control needs a catalog entry, and the page's `searchTerms` in `MyDockSettingsPage`, beside its anchor.
