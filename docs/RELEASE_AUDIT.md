# MyDock release audit — 27 September 2026

## Build and automated checks

- `./TestMyDock.sh`: 119 tests pass on the macOS 14 host, including exclusive profile-store locking, locale/time-zone clock formatting, the sleep-inclusive Stopwatch clock, persisted timing state, target-date Countdown math and backup behavior, defensive elapsed-time display, opt-in native Dock auto-save isolation, independent AI provider refresh, persistent local window-preview cache bounds, and Custom Dock tile geometry including the optional Trash card. The Swift Testing library supplied with this Command Line Tools installation links for macOS 14; the app itself targets macOS 13.
- `./BuildMyDock.sh --output build/MyDock-Release.app`: the current source builds a separate universal release while the older `build/MyDock.app` process remains open. The script rejects attempts to overwrite that running bundle, including an observed default invocation. The release is packed as `build/MyDock-Release.zip` without disturbing the older process. Strict `codesign --verify --deep`, both architecture checks, and ZIP integrity passed. The bundle declares macOS 13. Developer ID signing, notarization, and an updater are not configured.
- `./GenerateXcodeProject.sh` produces a checked-in Xcode app project with all 71 Swift sources, the original icon, the Focus Filter intent, a macOS 13 Info.plist, and Release hardened runtime plus the Apple Events entitlement. XcodeGen regeneration is stable and the project/plists pass `plutil`. `xcodebuild` cannot run with only Command Line Tools, so App Intents metadata, Focus discovery, and Developer ID distribution remain unverified; see [XCODE_BUILD.md](XCODE_BUILD.md).
- A DEBUG-only visual preview uses a temporary profile store and returns before the real Dock controller starts. Both the explicit environment flag and the preview bundle identifier activate this isolated path, so reopening the preview app without a shell environment stays safe. Live checks covered bottom/left/right Dock tiles, all onboarding steps, Manager, Settings, widget library, light/dark appearance, overflow navigation, Clock popouts on each edge, and the Countdown Date & Time and Duration controls. The Countdown popout was bounded to 300 points, and the final 960 × 560 isolated preview capture showed its value, mode picker, date field, actions, and explanatory text entirely inside the popout. A fresh default-size Manager screenshot exposed a clipped profile name; a reserved text-field height fixed it and a second live screenshot showed the complete title above the Preview toolbar. Profile save/discard, switching with unsaved edits, and two-item group movement were clicked through. Manager tiles now expose button actions to accessibility clients. Details are in [VISUAL_PARITY.md](reference/VISUAL_PARITY.md).
- Automated Dock tests use isolated preference backends. They do not write the machine's real Dock preferences.
- Production startup now checks for an older running MyDock copy and takes an exclusive lock before loading profiles or starting Dock management. A duplicate exits without attempting Apple Dock restoration. The lock behavior passed its fixture test; a live duplicate launch was avoided while an older copy remains active.
- A read-only check of this Mac's Dock preferences found 15 pinned tiles, all with types the auto-save reader recognizes. No Dock preference was changed.
- The Music artwork and Spotify metadata AppleScript snippets compile with `osacompile`; no Apple Event was sent to a player during this audit.
- A live London city search and forecast succeeded through the Weather widget in the isolated per-process preview. Celsius/Fahrenheit conversion and Current/Conditions/Hourly layouts updated live. No Location permission was requested; the selected city remains in that temporary preview store only.

## Source and data review

- No product `TODO`, `FIXME`, `TEMP`, `HACK`, `MOCK`, `STUB`, or `fatalError` markers remain. The two forced Accessibility bridges follow explicit Core Foundation type-ID checks. Tests contain fixed HTTP URL examples.
- Provider keys and access tokens are stored in Keychain and excluded from profile backups. The logging calls found in source report Dock recovery or shortcut registration errors, not credential values. The Now Playing UI no longer repeats raw AppleScript error text.
- Backup input has a 25 MiB cap, profile and item caps, URL policy checks, normalized bounded favicon data, and local-file validation for App Folder members. Import reports missing top-level and nested paths and does not activate imported profiles.
- Storage scans skip hidden files, package descendants, and symlinks; they run in a detached task after a user action, support cancellation, disclose skipped/capped results, and never delete files. Home and Library totals are separate because the locations overlap.
- Site icons are fetched only on an explicit action with bounded HTTPS requests. Spotify artwork uses a bounded credential-free HTTPS request to `i.scdn.co` and stays in memory. Opt-in window previews are stored locally in a private, size-capped macOS Caches directory for up to 24 hours, keyed by hashed app/title identity, excluded from backups, and cleared when disabled or Screen Recording access is revoked.
- The Custom Dock's system, network, window, and Now Playing monitors stop or pause their recurring work while the Dock is hidden. Idle/active CPU and long-running memory measurements have not been completed; multi-display verification also remains outstanding.
- Native Dock auto-save stays off by default. When enabled, it reads pinned apps and spacers every five seconds, observes an initial baseline, ignores MyDock's own successful applies, and saves external changes only to the selected profile. Unsupported Dock tiles pause automatic saving instead of being silently dropped. Its fixture test never touches the real Dock.
- The optional menu-bar profile title is stored in settings, displays the applicable native and/or Custom profile names for each setup mode, truncates long names, and retains full names in the tooltip. Model and migration tests pass; live menu-bar title layout remains unchecked.
- The Custom Dock now offers a right-click Switch Profile submenu on its surface, regular tiles, and minimized-window tiles. Custom selections activate locally; native selections use the same transactional Dock controller as the menu bar. The menu compiles, but pointer behavior and native switching require unlocked desktop acceptance.
- AI Limits refreshes each visible provider through an independent adapter. Codex reads its local app-server; Claude Code can share documented subscription windows through an explicitly configured status line, which writes only percentages and reset times to a bounded local snapshot. MyDock does not read Claude credentials or query a private OAuth endpoint. Stale samples expire after 30 minutes. Fixtures verify adapter failure isolation, local file validation, freshness, reset times, and window parsing. Other provider quotas remain unavailable. Official docs explain the remaining gaps: [Gemini CLI shows quota in `/stats model`](https://geminicli.com/docs/get-started/) but [forbids third-party use of its OAuth backend](https://geminicli.com/docs/resources/faq/); [GitHub's personal Copilot billing API](https://docs.github.com/en/rest/billing/usage) reports consumption but not entitlement allowance; [Cursor's API is for team administration](https://docs.cursor.com/en/account/teams/admin-api); [xAI's API limits](https://docs.x.ai/developers/rate-limits) are separate from [Grok subscription usage](https://docs.x.ai/grok/faq/). Claude setup is documented in [CLAUDE_CODE_LIMITS.md](CLAUDE_CODE_LIMITS.md), against Anthropic's [official status-line schema](https://code.claude.com/docs/en/statusline). Live provider accounts remain unverified.
- Codex's limit parser accepts fractional percentages, rounds them for the integer display, and rejects booleans as percentages. The updated fixture passes.
- Claude Code's status-line fields are parsed from a reduced local snapshot. Missing percentages and stale samples remain unavailable rather than displaying old or fabricated values.
