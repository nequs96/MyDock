**MyDock — final-build gap audit and design improvement plan**

> Historical audit, retained at its original path for existing references. Current implementation and acceptance status: [IMPLEMENTATION_STATUS.md](../IMPLEMENTATION_STATUS.md). Findings and “current” statements below describe that audit's date.


Audit date: 28 September 2026. Baseline: Dockset v0.2.6, the user's clean-room master specification, current source at `18a664a`, and the uncommitted popout-edge correction. This is an audit and work plan, not a completion claim.

**1. Current verdict**

MyDock has a substantial native implementation, but it is not yet a verified 1:1 reconstruction of Dockset. Remaining work includes missing interactions, freshness and state-management defects, visual differences, desktop acceptance, and release provenance. The gaps are not limited to optional account credentials.

The intended target remains close functional, interaction, and visual parity using original branding and assets. Public pages establish many behaviors but do not expose every application screen or state. Exact visual parity needs matched reference captures and side-by-side comparisons. Website-inspired typography by itself does not establish application parity.

**2. Priority definitions**

- **P0 — final-build blocker:** correctness, reachability, recovery, or release evidence that must be resolved before calling the app final.
- **P1 — parity requirement:** documented functionality or interaction still missing or materially different.
- **P2 — additional usability/customization:** improvements beyond the minimum reference behavior, supporting the user's request for a more appealing and customizable app.
- **Confirmed source gap:** code directly lacks or contradicts the required behavior. **Risk:** source suggests a failure that still needs a focused reproduction. **Unverified:** code exists, but adequate runtime evidence is missing.

**7. Code quality work that supports a reliable final product**

1. **Shared popout presentation.** Centralize sizing, header actions, scrolling, focus, dismissal, tab state, placement and draft ownership. Per-widget fixed frames have already produced repeated clipping fixes. Preserve specialized content rather than forcing every widget into an identical form.
2. **Refresh services with explicit lifecycle.** The shared scheduler is a good foundation. Extend it with per-provider deduplication, visible-tile freshness, latest-request semantics, cancellation and retry/backoff. Keep stored data separate from transient loading/error state.
3. **Exercise asynchronous transitions.** AI Limits/Activity, Weather, Stripe, Paddle, and Shopify now use request-generation and selection checks so stale responses and errors cannot overwrite a newer selection. Shopify also avoids persisting a refreshed credential after its request is superseded or the widget disconnects. AI provider collection checks cancellation between readers. Add delayed-response tests through injectable API transports to cover account/range changes, stale errors, and disconnect races; current fixtures cover collector cancellation and Alarm/Countdown/Hydration notification generation ordering, not delayed network responses or OS notification delivery.
4. **Reduce whole-app writes and invalidation.** `ProfileStore.commit()` encodes the entire state synchronously on the main actor; many views observe that entire store, and the panel is updated for state publications. Coalesce noncritical writes, isolate widget state, and preserve ordered writes and shutdown flush. Measure before and after.
5. **Split high-risk large files gradually.** `WidgetViews.swift` is 1,471 lines, `CustomDockWindowController.swift` 1,109, `DockModels.swift` 1,033 and `DockManagerView.swift` 892. Extract widget modules, presentation policies, notification coordinators and typed widget configuration without a gratuitous full rewrite. Keep migration compatibility.
6. **Make runtime dependencies injectable.** Production views often call singleton services directly. Add boundaries for EventKit, Keychain, process execution, permissions, clock and displays so failure states can be exercised without real credentials or destructive desktop actions.
7. **Bound subprocess reads and cancellation.** Closed for catalog and Codex quota reads: MyDock now drains stdout/stderr concurrently, enforces per-stream byte caps while reading, caps catalog listing at 20 seconds, and terminates then escalates to SIGKILL if needed. Shortcuts catalog reads propagate task cancellation. User-triggered shortcut execution has no imposed time limit. Regression coverage exercises simultaneous pipe pressure, bounded output, stdin closure, timeout reaping, and cancellation.
8. **Complete diagnostics.** A typed, bounded event recorder and opt-in redacted status export now cover lifecycle, native Dock, custom Dock visibility, persistence, Focus, backup, permission-status refresh, Weather errors, Stripe/Paddle/Shopify errors, and display fallback/recovery. The export excludes names, IDs, paths, URLs, notes, calendar content, credentials, and images by construction. Extend coverage to other widget and window-management failures, then verify the General-page export and useful failure traces on the desktop.
9. **Formalize migration policy.** Version 1 plus decode defaults and future-version protection exist. Add explicit migration fixtures when schemas change; do not invent migrations for versions that never shipped. Preserve corruption recovery and import safety.
10. **Add repeatable UI and performance evidence.** Seven Swift test files are included in a generated Xcode unit-test target and the SwiftPM suite. A separate Visual QA UI-test target now launches a disposable Debug preview and attaches light/dark, bottom/left/right, and long-Countdown screenshots. Its source parses and XcodeGen wires the scheme, but full Xcode execution and screenshot review remain unverified. Add focused error-state, accessibility, and performance scenarios; keep synthetic values in test/preview builds.

The strongest direction is a compact native utility with clear hierarchy and useful widget content. The current serif header and large rounded Settings sections echo the marketing website, but that does not establish the reference application's actual interface. | Surface | Current issue or risk | Recommended improvement |
|---|---|---|
| Dock | Uniform cards devote considerable width to widget names while data uses 7–9 pt text.
