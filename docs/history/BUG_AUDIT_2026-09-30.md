# MyDock code, performance and visual bug audit

30 September 2026. This audit continues the premium redesign in the existing application. Changes were made in place, preserving profile storage, providers, permissions, native Dock serialization and integrations. The pre-audit source and tests are preserved in `.build/bug-audit-baseline-20260930/`; existing uncommitted work was retained.

The audit found and repaired persistence, state ownership, cancellation, timer recovery and layout failures, and reduced unnecessary image and disk work. **Desktop interaction acceptance is still pending:** computer-use inspection returned a locked Mac. The development application was launched to export its real SwiftUI/AppKit views into 41 layout renders, but those renders do not establish native window, scrolling, keyboard, pointer or VoiceOver behavior.

## Findings and repairs

| Area | Failure or inefficiency | Change and evidence |
| --- | --- | --- |
| Pinning running apps and Trash | Runtime items have stable identities. Adding the same item to multiple profiles reused its ID, violating library-wide uniqueness and preventing persistence. | `ProfileStore.add` and `insert` assign a new identity when an existing profile owns it. A regression saves and reloads both profiles with the same runtime app and Trash. |
| Deleted profile drafts | Deletion through another surface could leave a dirty edit session that could never be saved, blocking close/quit. | Profile deletion clears its edit session centrally. The editor also selects a surviving profile after external deletion. Regression checks removal and saving the remaining drafts. |
| Direct Dock resizing | The resize handle changed the global size even when the active profile had an appearance override. The visible Dock could therefore ignore the gesture while other profiles changed. | Resizing follows the profile's inheritance choice, validates the size, coalesces writes and flushes at gesture end. Regression checks both independent and inherited sizes after reload. |
| Editor preview interaction | Preview tiles could open apps or real widget editors and mutate saved configuration. | Preview click and long-press actions are guarded; item hit testing and accessibility actions are suppressed. Preview scrolling remains available. Requires native input acceptance. |
| Draft/preset preview appearance | Widget tiles looked up saved/global settings even when the preview supplied a different appearance. Geometry and widget presentation could disagree. | `WidgetCompactView` accepts resolved presentation settings from `CustomDockView`. The render matrix includes profile overrides and all three Dock positions. |
| Hidden workspace commands | Retained Settings/editor pages were visually hidden but their keyboard shortcuts could remain active. | Inactive pages are disabled as well as hidden, retaining drafts without active controls. Requires native keyboard acceptance. |
| Appearance sliders and Undo | Each intermediate drag value could synchronously encode and atomically write the entire library, and record another history/Undo step. | Sliders use the revisioned coalescing writer; history and Undo capture the gesture's initial appearance once, and release flushes it. Direct resize uses the same persistence path. Synthetic comparison below. |
| State and recovery files | Profile state and native transaction records were written with default file permissions. The transaction reader loaded the whole file before checking it. | New storage directories use owner-only permissions; state and journal files use `0600`. Journal reads use the existing bounded archive reader. Regression verifies modes and rejection of an oversized sparse file without deleting recovery data. |
| Shared widget refresh failures | Two widgets awaiting the same failing request published/counting its failure twice, increasing backoff prematurely. | The owned request publishes its result once; awaiters only wait for completion. A regression reproduced duplicate error publications and now expects one load and one publication. |
| Window capture cancellation | A cancelled capture could finish after re-enabling previews and overwrite newer work or clear its task slot. | Capture generations reject obsolete completions. Injected-capture regression finishes the old request after a new one starts and verifies only the new image is published. |
| Window title changes | An existing accessibility identity could retain the previous document's image when its title changed. | Image and retry caches track the current unique window cache identity. Regression verifies that a renamed document loses its old preview. |
| Permission changes during capture | Work started while screen capture was permitted could publish after permission was revoked. | Permission is checked again before publication; inaccessible memory/disk previews are cleared. Injected permission regression verifies rejection. |
| Hidden timers after wake/clock changes | Sleeping tasks used elapsed time while persisted timers used wall-clock deadlines. A clock jump could leave a completed hidden timer marked running until the old sleep ended. | The lifecycle coordinator reschedules on system clock changes and wake, using the current deadline. Regression advances an injected clock and finishes both hidden Focus and Countdown timers. |
| Native auto-hide recovery | A failed re-enable attempt rolled back its immediate preference and removed an older session's restore record, losing the true original value. | Successful rollback removes only a record created by that attempt. Regression changes the preference externally, fails re-enable, and restores the original value on exit. |
| Cancelled queued native apply | A cancelled request waiting behind another Dock operation could still write preferences when its turn arrived. | Apply checks cancellation after acquiring the operation gate. Regression holds an isolated gate, queues/cancels apply and verifies no write or Dock restart. |
| Native auto-save failures | The monitor remembered a new layout before its disk write succeeded. An unchanged next poll cleared the warning and never retried. | Unchanged observations retry outstanding persistence and preserve the error until saving succeeds. Regression blocks the state-file path, verifies the error persists, unblocks it and verifies reload. |
| Quick Look magnification work | Small size changes started independent thumbnail requests and added many resolutions to an unbounded cache. | Retina resolution buckets reuse images; obsolete requests are cancelled; the cache is capped at 256 entries/32 MiB. Native magnification/Quick Look timing remains pending. |
| Weather cache growth | Cached locations/coordinates accumulated without a limit, including movement of current-location weather. | Expired entries are pruned and the oldest entries evicted above 128. An injected provider regression checks eviction and reuse of the newest forecast. |
| Small-window sheets | Presets had a fixed 650-point height; long widget configuration content had no bounded scroll area. Resolution notes could crowd out preset controls. | Gallery/preset heights follow available space; preset review content scrolls with creation actions retained; widget sheets size short editors to content and scroll long editors with a visible close control. Three configuration sheet renders included. Native sheets still need acceptance. |
| Shortcut recorder wording | The sheet said Cancel even after a shortcut had already been saved immediately. | The resting action now says Done; recording still offers Cancel. Existing shortcut validation and registration are preserved. |

Polling/data/lifecycle coordinators release their sleeping work on teardown. Window sampling and capture remain asynchronous. The four-request provider limiter, stale-request generations, typed drag data, transaction verification/rollback, notifications, Keychain credentials and profile draft merging remain in place.

## Scope reviewed

The review covered the application delegate and workspace shell; native/custom Dock controllers, geometry, overflow, resizing, auto-hide/reveal and display selection; profile CRUD, staged edits, history, presets, backups and the revisioned writer; all seven Settings pages, search/navigation, gallery/category/variant flows, onboarding, profile menus/context menus, link/favicon editing, folder browsing and shortcut recording.

Widget review covered the shared registry, compact/card/popout presentation, refresh ownership, limiter, lifecycle coordinator, timers and notification generation, weather/location, calendar/reminders, apps/files/folders/Trash/AirDrop, running apps/window previews/badges, system/network activity, media, market data, business connections and AI data. Existing provider fixtures and regression suites were used instead of exercising personal accounts or changing the user's macOS Dock.

No speculative behavioral rewrites were made for ambiguous product choices such as duplicating an already running Focus Timer. Existing safeguards were retained where inspection found them adequate, including cached Apple Dock visibility sampling, validated accessibility CF bridges, provider request limits, recovery journaling and import identity sanitization.

## Verification

- `./TestMyDock.sh`: Swift Testing reports **205 tests in 14 suites passing**, including 14 new regression cases. The live native Dock case and synthetic performance capture are opt-in and skipped in the normal run.
- `MYDOCK_PERFORMANCE_OUTPUT="$PWD/.build/audit-performance-after.json" ./TestMyDock.sh --filter PerformanceBaselineTests`: the isolated synthetic performance case passes. Benchmarking is run separately from asynchronous regressions to avoid blocking their executor with the deliberately heavy synchronous writer scenario.
- `./BuildMyDock.sh --output build/MyDockAudited.app`: universal release succeeds for **arm64 and x86_64**, targeting macOS 13. Both slices build from the same source fingerprint. Ad-hoc signature verification passes.
- Xcode project regenerated with the new configuration sheet and regression suite. Full Xcode/UI tests are unavailable on this Command Line Tools host.
- `git diff --check` passes.
- Final sources, tested preview, release binary, logs and 41 layout renders are hashed in `BUG_AUDIT_VERIFICATION_2026-09-30.json`. Earlier redesign verification files describe their earlier builds.

An initial performance-enabled combined run exposed test executor contention rather than a product failure: its synchronous 2,000-item benchmark blocked asynchronous test continuations beyond their short wait deadline. The regression wait is now bounded at ten seconds; the benchmark is verified separately. The final normal and benchmark runs pass.

## Performance evidence

Debug synthetic measurements on this 8-processor Mac, macOS 26.5.1. Geometry scenarios have 30 samples of 100 iterations each; disk scenarios are illustrative single runs.

| Scenario | Before audit | After audit |
| --- | ---: | ---: |
| 7-widget geometry, median | 0.0454 ms | 0.0474 ms |
| 30-widget geometry, median | 0.1499 ms | 0.1529 ms |
| 60-widget geometry, median | 0.2801 ms | 0.2825 ms |
| Encode and atomically write 50 profiles / 2,000 items | 92.18 ms | 91.51 ms |

In the same post-audit writer fixture, **20 immediate appearance writes took 1,803.91 ms; 20 coalesced updates with a final flush took 91.67 ms**. This demonstrates the avoided intermediate disk/encoding work. It is not an application-wide speed multiplier, frame-rate, energy or native animation measurement. Geometry remains comparable; a few percent of single-host variance is not treated as a regression or speedup.

## Layout evidence and remaining acceptance

The 41 real-view renders cover editor widths 900/1160/1440, gallery widths 760/960/1200, all Settings pages at 900 and 1160, dark/light layouts, onboarding steps, search/results/empty states, About, Clock/Focus/Sticky Note popouts and configuration sheets, bottom/left/right Dock previews and long-Dock overflow. Representative images were inspected at full size and the entire matrix reviewed as a contact sheet.

The DEBUG renderer uses an isolated `ProfileStore`, inert sample cards and native hosting views. It flattens scroll viewports because their compositor content cannot be reliably cached offscreen. It is excluded from release. These outputs establish first-viewport layout and presentation, not scroll positions, native window/titlebar compositing, menu dismissal, input focus, dragging or accessibility acceptance.

After the Mac is unlocked, the remaining checks are actual minimum/medium/large windows; scrolled Settings/gallery/provider content; sheets and confirmations; profile actions and keyboard switching; drag/drop, reorder, hover and magnification; reveal/auto-hide and multi-display placement; VoiceOver/reduced-motion/contrast; permission transitions and real provider accounts. Real native Dock apply/restart/rollback must be exercised in the documented disposable acceptance environment. macOS 13 and Intel runtime acceptance also remain unverified despite a successful build.
