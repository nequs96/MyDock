## Investigation and data flow

The old AddLibrary combined app discovery, widgets, spacers and commands into a search/segmented-filter list. Its private catalog found `.app` directories using shallow filesystem enumeration and created DockItems without validating their metadata or executable. On this Mac, several old Adobe directories still end in `.app` but have no `Contents/Info.plist`. These were filesystem remnants rather than working installed applications. No vendor blacklist is used in the fix.

AddLibrary now obtains `InstalledAppScan` from the shared InstalledAppCatalog. User/local/system application roots, System Applications and CoreServices Applications are scanned with package boundaries, depth and entry budgets. Finder is an additional validated NSWorkspace result. Candidates must resolve to readable real `.app` directories with current APPL metadata, identity/name, executable and a supported Mach-O architecture. Nested services, agent/background apps, aliases and unsupported executables are rejected. Canonical path plus bundle identifier/version deduplication collapses repeat copies while retaining distinct versions and unrelated same-name products. A selected saved URL wins during launch resolution; bundle-ID relocation is a fallback.

Discovery runs in a detached cancellation-aware task. A fresh scan replaces the inventory on reopen, Refresh, app activation and volume mount/unmount. Cached paths are not reused as the inventory. Visible app rows asynchronously resolve icons from the validated installed path; a bounded thread-safe icon cache stores small PNGs. Add revalidates availability before insertion. Nonstandard application locations remain accessible through Choose Application; this deliberately avoids a whole-filesystem or arbitrary mounted-volume scan.

Widget discovery comes from WidgetRegistry and its real categories. Shared WidgetCardPreview provides inert previews of existing renderers; AI Activity now uses the same compact renderer as the live Dock. System tiles route to the existing spacer/application/folder/file/link editor actions. Search covers the current category's visible names and useful aliases; All results retain widget sections and separate Applications/System groups. Added state checks the selected profile and additions made during the open browser. Click/Return add without closing, standard additions prevent duplicates, and the existing width context menu explicitly offers Add Another for widgets. Spacers are intentionally repeatable. Command-K retains its separate command interface.

AI Activity remains local usage history, distinct from AI Limits/account quota. WidgetDataCoordinator owns query coalescing, freshness, errors and updates. AIActivityReader parses bounded local Codex/Claude/Grok logs into daily points and range totals; those persisted snapshots feed both tile and popover. Unreadable partial refreshes now preserve previously available data, while a successful empty scan can replace it. Account detection only runs when local activity is unavailable; account issues do not hide valid usage history. Recovery uses the existing provider opening/sign-in route. No credentials were added or transmitted and no AI task was started.

## Resulting experience

Add Item is a bounded two-pane customization browser: compact Search/category navigation, grouped visual widget previews, system previews and dense installed-app rows with actual icons. It remains open for multiple additions. Added text/checkmarks, native controls, icon help/labels, focused Search, Up/Down selection, Return, Escape-to-clear and Escape-to-close work with the editor architecture. Empty searches and discovery failures have intentional states and Retry.

AI Activity is a compact 372-point content surface. Header actions are small, provider/range controls are compact, tokens lead the aligned metrics, and the daily chart uses human-readable K/M/B axis labels. Provenance, partial-log information and updated time sit below the activity. Setup has one provider recovery action; failure has Retry. Refresh retains metrics and chart. The generic large Close/freshness footer is removed for this popover only; existing Customize and native Escape/outside dismissal remain.

The tile shares this hierarchy at 54/108/144/196-point widths, with a restrained provider glyph and one metric. At 54 points the sample rounds to `644M+`; wider tiles show `643.9M+` (locale-aware decimal separator). Partial usage uses + with detailed help, setup says Connect, unavailable states remain neutral. Refresh overlays do not change the accessible button role.

## Primary API references

Apple documents [application directory search domains](https://developer.apple.com/documentation/foundation/filemanager/searchpathdirectory/applicationdirectory), [NSWorkspace application URL lookup](https://developer.apple.com/documentation/appkit/nsworkspace/urlforapplication(withbundleidentifier:)) and [thread-safe installed-path icon lookup](https://developer.apple.com/documentation/appkit/nsworkspace/icon(forfile:)). [Launch Services bundle keys](https://developer.apple.com/library/archive/documentation/General/Reference/InfoPlistKeyReference/Articles/LaunchServicesKeys.html) distinguish agent/background bundles. The implementation treats API results as candidates and validates filesystem contents before display.
